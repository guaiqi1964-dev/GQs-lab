# 恶魔 AI 策略与「再来一局」功能说明

本文档记录优化修复版 v3 新增的两项内容：**更聪明的恶魔 AI** 与 **重开一局**。

---

## 一、恶魔 AI 是怎么变聪明的

### 1.1 原来的恶魔有多弱

原程序里恶魔的决策逻辑（反汇编 `0x4028C3` 起的恶魔回合）是：

| 情况 | 原程序的选择 |
|---|---|
| 用过放大镜且看到空弹 | 打自己（正确） |
| 其他情况 | **纯随机 50%** |

也就是说：**没见过牌的时候它就是掷硬币**。而且原程序的单人对局里
这个函数根本不会被调用（见 `BUGFIXES.md` 的 BUG #1），所以它连掷硬币的机会都没有。

用无头模拟（`__recovery/ai_bench2.py`，4000 局/行）量化一下：

| 恶魔策略 | 玩家胜率 |
|---|---|
| **原来的纯随机 50%** | **91.4%** |
| 新的休闲启发式 | 65.6% |
| **新的高手 minimax** | **50.9%** |

原来的恶魔几乎等于不会还手——这就是为什么单人模式玩起来毫无压力。

### 1.2 新 AI 的核心：胜率搜索

新实现（`namespace ai`）把这一局建模成一个**有限状态博弈**，然后搜出胜率：

```
状态 = (剩余实弹, 剩余空弹, 我方血量, 对方血量, 当前伤害, 谁在行动)
动作 = { 打对方, 打自己 }
```

用记忆化递归求每个状态下**当前行动方的胜率**，存成 0..10000 的整数
（避免浮点误差）。关键转移：

```cpp
// 打对方
if (l > 0) {                       // 命中
    nh = oh - dmg;
    after = (nh <= 0) ? WIN : 10000 - solve(l-1, b, mh, nh, 1, turn^1);
    miss  = (b > 0) ? 10000 - solve(l, b-1, mh, oh, 1, turn^1) : after;
    shootFoe = (l*after + b*miss) / total;
}
// 打自己
if (b > 0) {
    cont = solve(l, b-1, mh, oh, dmg, turn);        // 空弹 → 还能继续行动
    hit  = (mh-dmg <= 0) ? LOSE : 10000 - solve(l, b-1, mh-dmg, oh, 1, turn^1);
    shootSelf = (b*cont + l*hit) / total;
}
best = max(shootFoe, shootSelf);
```

这里最重要的两件事，是原程序完全没做的：

1. **打自己打出空弹可以继续行动**（`cont` 那一项）。
   所以"已知下一发是空弹 → 打自己"是白赚一次行动权，而不是浪费。
2. **把自己的血量状态一起算进去**：残血时打自己中弹就等于自杀，胜率搜索
   会自然地避免这种送死行为，而在血量健康时更敢赌。

状态空间很小（实弹 0..4、空弹 0..4、血量 0..6 双方、伤害 1..2），
所以搜索是瞬时的，不需要任何近似。

### 1.3 道具也用得更讲究

`demonUseItems()` 现在的判断顺序：

| 时机 | 动作 | 理由 |
|---|---|---|
| 血量 ≤ 上限一半 | **烟** | 最稳的收益，先补血 |
| 还不知道下一发 | **放大镜** | 信息就是优势，看了牌再决定 |
| 确定是空弹 | **手铐** | 白赚的额外行动，配合空弹连打 |
| 确定是实弹 | **小刀** | 伤害翻倍，能一击致命时必用 |
| 实弹占比 >75% 且自己残血 | **饮料** | 把危险的那一发退掉 |
| 中了手铐还想再确认 | **放大镜** | 额外行动也值得先看牌 |

道具使用有 `guard` 上限（4 轮），避免道具互相触发导致死循环。

### 1.4 加了难度选项

因为新 AI 明显更强（91% → 51%），直接替换会让人措手不及，
所以单人模式增加了一个难度选择：

```
请选择恶魔的难度：
1.休闲（恶魔偶尔犯糊涂，道具用得少）
2.高手（恶魔会算胜率，道具用得很精，推荐）
```

- **休闲**：只有"确实用放大镜看到了结果"时才做正确判断，
  其余情况按血量粗略估计（落后时更激进地赌空弹），
  放大镜只有 50% 概率想起来用，也不喝饮料。
- **高手**：完整的胜率搜索 + 全部道具。

## 二、「再来一局」功能

### 2.1 原来的问题

原程序分出胜负后直接 `exit(0)` —— 只能关掉重开。

### 2.2 现在的流程

一局结束后会显示：

```
==================== 本局结束 ====================
结果：你赢了
1.再来一局
2.退出游戏
==================================================
```

选「再来一局」会回到模式选择，可以换模式、换难度继续玩；
选「退出游戏」才打印 `感谢游玩，再见！` 并结束。

实现上做了两处结构调整：

1. 把单人对局从 `void playSingle()` 改成 **`int playSingle()`**，
   返回 0（玩家赢）/ 1（玩家输），不再在里面 `exit(0)`。
   双人模式同理返回 0/1。
2. 主循环负责反复开局：

```cpp
for (;;) {
    showModeMenu();
    mode = askNumber(1, 2);
    if (mode == 1) { showDifficultyMenu(); /* 设难度 */ }
    resetGame();                       // 清空上一局的所有状态
    g.money = rnd(0, 999999) / 100.0;  // 每局重新抽奖金
    winner = (mode == 1) ? playSingle() : playDuo();
    if (!askReplay(winner)) break;
}
```

`resetGame()` 会清空弹夹、伤害、以及四个 `Player` 的血量与道具，
所以连续玩很多局不会残留上一局的状态。

## 三、验证结果

本机 MinGW-w64 GCC 16.2.0 实测：

| 项目 | 结果 |
|---|---|
| 编译（`-Wall -Wextra`） | **零警告零错误** |
| 难度菜单 | 两个选项都能正常进入对局 |
| 分出胜负 | 赢/输两条路径都正确显示结果 |
| 再来一局 | 能连续开局，模式与难度每局都可重选 |
| 退出 | 打印 `感谢游玩，再见！` 后正常结束 |
| AI 决策正确性 | 用放大镜看到「空弹」后打自己、看到「实弹」后打对方，无矛盾 |
| 道具使用 | 放大镜 / 手铐 / 小刀 / 烟 都会在合适时机使用 |

AI 强度对比（无头模拟，`ai_bench2.py`，各 4000 局）：

```
player                         demon                   player%   demon%
--------------------------------------------------------------------------
no items (baseline)            old: random 50/50         91.4%      8.6%
no items (baseline)            casual heuristic          65.6%     34.4%
no items (baseline)            sharp minimax             50.9%     49.1%
uses magnifier                 old: random 50/50         91.3%      8.7%
uses magnifier                 casual heuristic          68.8%     31.1%
uses magnifier                 sharp minimax             52.1%     47.9%
```

可以看到：高手 AI 把对局拉回到接近五五开（双方道具获取是对称的，
差异只来自决策质量），既不是原来那种 91% 的"送分局"，
也不是打不过的墙。

## 四、如果你想继续调

- **觉得高手还是太难**：把 `demonUseItems()` 里的道具使用条件收紧，
  或把 `ai::shouldShootSelf` 换成 `demonShouldSelfShoot` 的休闲分支。
- **想让它更凶**：可以让恶魔在 `me.hp` 领先时也优先打对方（现在是靠胜率自动权衡），
  或者提高道具补给量。
- **想加第三个难度**：在 `enum class Difficulty` 里加一项，
  在 `demonShouldSelfShoot()` 与 `demonUseItems()` 里加对应分支即可。
