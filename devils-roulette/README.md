# 恶魔轮盘赌 · 逆向还原与优化

把一个自己早年写的小游戏从**只有 EXE、源码已丢失**的状态还原回可维护的 C++ 源码，
修掉其中的 bug，重新设计 AI，并加上一些体验改进。

> 原程序：`恶魔轮盘赌.exe` —— 一个用 MinGW-w64 / GCC 4.9.2 编译的控制台小游戏，
> 构建于 2024-10-21，单文件项目。

---

## 一、为什么能还原得这么完整

原 EXE **没有加壳**，而且当年是用**带调试信息**的方式编译的，所以程序里保留了：

| 内容 | 大小 / 数量 |
|---|---|
| COFF 符号表 | 22138 条符号（约 934 KB，位于文件尾部的 overlay） |
| 未命名 DWARF 调试段 | `.debug_info` / `.debug_line` / `.debug_str` 等，约 400 KB |
| `.pdata` x64 异常表 | 2527 条 `RUNTIME_FUNCTION`，给出**精确**的函数边界 |
| `.rdata` 中的游戏文案 | 1039 条 GBK 字符串 |

因此函数名、函数边界、调用关系、全部界面文案都是**读出来的**，不是猜的。

### 还原流程

1. **PE 解析** —— 段表、映像基址、overlay 起止。
2. **COFF 符号表解析** —— 从 overlay 里解出全部符号名与地址；长名字通过字符串表解析。
3. **`.pdata` 解析** —— 拿到每个函数的准确 `[start, end)`。
4. **`.debug_*` 定位** —— 段名是 `/4`、`/19` 这种 COFF 长名引用，需要先还原字符串表才能认出
   它们分别是 `.debug_aranges` / `.debug_info` / `.debug_abbrev` / `.debug_line` 等。
5. **自研 x86-64 解码器** —— 机器上没有 objdump/IDA，于是用 Python 写了一个够用的
   反汇编器（`tools/dec2.py`），对 `.text` 做线性扫描，成功解码 151860 条指令。
6. **字符串交叉引用** —— 把每条 RIP 相对寻址的目标解析出来，
   于是每个函数"引用了哪些文案"一目了然，函数用途也就确定了。

## 三、找到的 5 个 bug

| # | 问题 | 影响 |
|---|---|---|
| **1** | **单人模式里恶魔永远不会行动** | 主循环因编译期常量优化，永远走不到恶魔回合；恶魔回合的 2635 字节连同 `"现在是恶魔的回合"`、`"有趣"` 等文案全是死代码。**玩家不可能输。** |
| **2** | 道具种类取 `randomInt(0,4)` 即 0..3，而道具共 5 种 | **第五种「饮料」永远抽不到** |
| **3** | 「获得了 N 个道具」打印的是 `min(8-已有, 4)` | 显示的是**剩余上限**，不是实发件数 |
| **4** | `恶魔生命:` 被还原成 `恶魔的生命:` | 文案不一致（还原过程中引入） |
| **5** | 清屏前没有 `fflush(stdout)` | 一旦重定向输出，`printf` 的内容会被 `system("cls")` 吞掉，只剩一串 `0x0C` |

BUG #1 的反汇编证据（主循环 `0x402EC3`）：

```
0x402ECB  loop:
0x402ED1    test eax,eax          ; [someFlag] 编译期已知为 0
0x402ED3    jne  0x402EE6         ; ← 永远不跳，恶魔分支被绕过
0x402EF3    call 0x401967         ; danrenplay（玩家回合）
0x402EFA    call 0x4028C3         ; demonTurn（恶魔回合）—— 到不了
0x402EFF    jmp  0x402ECB         ; 无限循环，永不返回
```

详见 [`docs/BUGFIXES.md`](./docs/BUGFIXES.md)。

## 四、优化与新增功能

### 4.1 代码层面

| 方面 | 还原版 | 优化版 |
|---|---|---|
| 道具逻辑 | 「你/恶魔/玩家A/玩家B」四套重复分支 | 统一 `useItem(Player&, int)` |
| 输入校验 | 每处各写一遍 | 统一 `askNumber(lo,hi)`，并清掉残留字符防死循环 |
| 状态管理 | 一堆全局布尔量双方共用 | 收进 `Player` 结构体 |
| 魔法数字 | `1/4/8/6` 散落各处 | 集中到 `namespace rules` |
| 道具表 | 名称与说明各一份 | 合并为 `kItems[]` |
| 菜单编号 | 散落的 `i+3` / `choice>=3` | 统一 `kMenu*` 常量 |
| `wait()` | 调用 Windows `Sleep()` | 用 `<ctime>` 实现，跨平台 |

### 4.2 恶魔 AI：从"掷硬币"到胜率搜索

原来的恶魔**没见过牌时就是 50% 随机**。现在把对局建模成有限状态博弈：

```
状态 = (剩余实弹, 剩余空弹, 我方血量, 对方血量, 当前伤害, 谁在行动)
动作 = { 打对方, 打自己 }
```

用记忆化递归求每个状态下当前行动方的胜率。两个关键点原程序完全没用上：

1. **打自己打出空弹可以继续行动** —— 所以"已知是空弹就打自己"是白赚一次行动权；
2. **把自己的血量一起算进去** —— 残血时打自己中弹等于自杀，搜索会自然避开。

无头模拟各 4000 局的结果：

| 恶魔策略 | 玩家胜率 |
|---|---|
| 原来的纯随机 50% | **91.4%** |
| 新的休闲启发式 | 65.6% |
| **新的高手 minimax** | **50.9%** |

因为强度跨度较大，单人模式加了难度选择（休闲 / 高手）。
详见 [`docs/AI_AND_REPLAY.md`](./docs/AI_AND_REPLAY.md)。

### 4.3 体验改进

- **分出胜负后可再来一局**（原来直接 `exit(0)`），模式与难度每局可重选；
- **行动菜单新增第 8 号选项「查看道具效果」** ——
  忘记道具作用时随时重看，且**不消耗行动、不切换回合、不消耗道具**。
  详见 [`docs/ITEM_HELP_OPTION.md`](./docs/ITEM_HELP_OPTION.md)。

## 六、编译

### 依赖

- MinGW-w64 g++（支持 C++17 即可；本项目在 GCC 16.2.0 上验证通过）

### 一键编译

```bat
cd src
build.bat
```

### 手动编译

```bash
g++ -std=c++17 -O2 -Wall -Wextra \
    -finput-charset=UTF-8 -fexec-charset=GBK \
    -o 恶魔轮盘赌.exe optimized.cpp
```

> ⚠ **`-fexec-charset=GBK` 必须加。**
> 新版 GCC 默认把窄字符串按 UTF-8 编码，而原程序是 GBK(CP936)，
> 不加这个参数中文在 CP936 的 Windows 控制台会显示成乱码。

### 打包成单文件 EXE

```bash
g++ -std=c++17 -O2 -s -static -static-libgcc -static-libstdc++ \
    -finput-charset=UTF-8 -fexec-charset=GBK \
    -o 恶魔轮盘赌修改版.exe optimized.cpp
```

在 Linux/macOS 下调试时，把 `clearScreen()` / `pauseScreen()` 里的
`"cls"` / `"pause"` 换成 `"clear"` / `"read -n 1"` 即可。

## 七、玩法

单人模式为**你 vs 恶魔**，双方各 6 点生命（双人模式 4 点）。

- 每回合开始前告知弹夹里有几发**实弹**、几发**空弹**，双方各补给道具（上限 8 个）；
- 每回合可选择：向对方开枪 / 向自己开枪 / 使用道具 / 查看道具效果；
- **对自己开枪若为空弹，可以继续行动**；对对方开枪则无论结果都结束行动；
- 五种道具：
  - **放大镜** —— 知道下一发子弹是空弹还是实弹
  - **手铐** —— 本回合多一次行动
  - **小刀** —— 下一发若是实弹则伤害 +1
  - **烟** —— 回复 1 点体力
  - **饮料** —— 退掉一发子弹

- 本项目是对**自己编写的程序**做逆向与维护，仓库内**不包含**原 EXE 与任何编译产物
