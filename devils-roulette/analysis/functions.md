## 从 `build_gun_duo()`（0x40157E）逐条还原的算法

```c
/* ① 实弹与空弹的数量各自独立取 [1,4] → 一回合共 2~8 发 */
shi  = randomInt(1, 4);      /* 0x401590 */
kong = randomInt(1, 4);      /* 0x4015A5 */
printf("%d发实弹,%d发空弹\n", shi, kong);

/* ② 先按顺序填入，再随机位置洗牌（0x4015F5 起的循环，索引 1..shi+kong） */
for (i = 1; i <= shi + kong; ++i) {
    r = randomInt(1, shi + kong);
    if (r <= shi) { bullet[r] = 2; --shi; }   /* 实弹 */
    else          { bullet[r] = 1; --kong; }  /* 空弹 */
}

/* ③ 显示"还能再拿几件"，实际每回合补 4 件 */
got = min(8 - sum(daoju[]), 4);               /* 0x401693..0x4016B7 */
printf("你获得了%d个道具:\n", got);            /* 0x4016C6 */

/* ④ 每回合真的补 4 件，种类取 randomInt(0,4) —— 注意索引范围是 0..3 */
for (i = 1; i <= 4; ++i) { d = randomInt(0, 4); ++daoju[d]; ... }
```

**两个值得注意的原始实现细节：**

1. 道具种类取的是 `randomInt(0, 4)`（即 0..3），而道具数组有 5 个槽位
   （放大镜/手铐/小刀/烟/饮料）——所以**第五种"饮料"可能永远不会被随机发到**。
   这很可能是原作者的一个笔误（应为 `randomInt(0,4)` 取满 5 种）。
2. 屏幕上打印的"获得了 N 个道具"其实是**剩余可携带上限**
   （`min(8 - 已有, 4)`），而每回合实际发放的是固定 4 件。
   所以开局背包为空时会显示"获得了8个道具"，但实际只进 4 件。
   这也解释了规则文本里"获得4个道具作为补给（上限为8个）"的说法。

还原版**保留了这两个行为**，以保证与原程序一致；
如果你想把它们当作 bug 修掉，见 `恶魔轮盘赌.cpp` 里对应位置的注释。

## 核心规则文本（摘自程序内 .rdata）

```
你和恶魔都各有6点生命
每一回合开始前，你将知道一共有几发实弹，几发空弹，同时双方都将获得4个道具作为补给（上限为8个）
每一回合，你可以选择对自己开枪，对恶魔开枪或者使用道具
如果你对自己开枪，若为空弹，则可以继续行动，否则，停止行动
如果你对恶魔开枪，无论如何，都将停止行动
道具一览：
放大镜：可以知道下一发子弹是空弹还是实弹
手铐：增加一次本回合的行动次数
小刀：若下一发子弹为实弹，则伤害+1
烟：可以回复1点体力
饮料：可以退一发子弹
```
